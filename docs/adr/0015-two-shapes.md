# Two shapes: set and grid; segmentation and detection are heads on the grid

soma's core commits to exactly two data shapes. The **set** shape (`(N, D)` features, `MILLearner`) serves classification, ordinal, regression and survival heads. The **grid** shape (`(D, h, w)` token grids, `DenseLearner`) serves segmentation and detection, which are heads on it, not pipeline families. Everything else is a head, a sampler, or benchmark-side code. `Pipeline.train` dispatches on the shape alone: `train_one_fold` (set) and `train_one_grid_fold` (grid).

## Why

The grid path had grown one fold function per task (segmentation, detection, pixel classifier) plus a closed-form probe fold, two models (`SegmentationModel`, `LiveSegmentationModel`), a parallel live dataset/loader/config branch, a private evaluator (`_evaluate_grid`) and a mutable detection threshold on the head. Live detection was impossible because targets were precomputed per sample; a model trained elsewhere could not be scored; and every artefact writer lived inside a fold.

## Decisions

- **One batch, one model, one learner.** `GridBatch(features, pixels, targets, sample_ids)`: `features` are cached grids, `pixels` the live path's input; an image-prior decoder reads `pixels` as a named side input (a cached batch for such a decoder carries both), never `targets["image"]`. `DenseModel(decoder, head, *, encoder=None, adaptor=None)` runs `pixels -> encoder -> adaptor -> decoder -> head`; the feature adaptor is the `adaptor` stage. `DenseLearner` is the one grid learner and gains `predict_step`.
- **The live path is a frozen stage inside the model.** `soma.extract.live_encoder(...)` is the only live-path code that speaks slide2vec: it wraps the `DenseEncodeKit` in a parameter-free `FrozenEncoder` (`geometry`, `feature_dim`, `input_device="cpu"`, `preprocessor()`), probe-encodes once, and is built once per run and shared across folds. The stage never enters an optimizer or a checkpoint. `TileImageSource` serves the pixels under the same id / geometry / spacing contract as a `GridSource`. `soma.testing.FakeEncoder` is a parameter-free stand-in that passes `check_encoder_stage`.
- **Raw targets, encoded by heads.** Datasets yield physical-unit supervision: a `(H, W)` label map, or level-0 points `(K, 3)` with an optional ignore map. Heads encode it at loss time against their bound geometry (`DetectionHead` renders its Gaussian heatmap on device), so one annotation serves any encoder stride and live detection works by construction. Grid heads declare `target_kind` (`label_map` | `points`); `loaders` refuses a mismatched target source and checks that the fold shares the head's geometry. Class schemes fold into the target sources (`LabelMapSource` label remap, `PointSource` `class_remap` / `drop`).
- **Two grid prediction nouns; `evaluate` dispatches on the noun.** `PointPredictions` (level-0 `sample_id, x, y, class, score`, `classes`, `match_distance_px`, parquet) and `LabelMapPredictions` (`{id: (H, W) uint8}`, PNGs + `index.parquet`) both carry the full id set, so ADR 0014's strict id equality holds. `soma.evaluate` matches points against a `PointSource` (Hungarian by default; `matching` / `match_distance` are metric-leaf params) or counts label maps against a `LabelMapSource`; the grid metrics are registry reducers over per-image counts. `soma evaluate` scores external label-map directories and points files.
- **Thresholds are frame operations.** `DetectionHead` emits every peak above `min_score`; `PointPredictions.with_threshold` and `soma.evaluation.sweep_threshold` choose the operating point; training-time validation uses a fixed `validation_threshold`, so `EarlyStopping`'s hold-at-floor logic is unchanged. The mutable `score_threshold` and `detection_thresholds.json` are gone; without a tune split the pipeline scores test at `validation_threshold`.
- **Artefacts are predict callbacks.** `SaveOverlays`, `SaveProbabilities` and `SaveHeatmaps` sit next to `SaveAttention`. Every grid run writes `predictions_<split>.parquet` (points) or `predictions_<split>/` (label maps) for tune and each test split; per-sample confusion is recomputable from the label maps, so `confusion_evidence_tune.json` and its resume path are gone.
- **Pixel classifiers are deleted.** The decoder-free sklearn path had its own fold, config section and evaluator. It is rebuildable on the verbs: a `GridSource` and a `LabelMapSource` give features and labels, sklearn fits, `LabelMapPredictions` + `soma.evaluate` score it.
- **The HEST probe is a benchmark-side predictor.** Core gains `RegressionHead(num_outputs=G)` (`value_<k>` columns) and `mean_pearson`. The closed-form ridge+PCA probe moves to `soma/benchmarks/hest/` as `RidgePCAProbe.fit(...).predict(...) -> Predictions`, and `HestBenchmark.run` composes extract, fit, predict and evaluate itself. `training.method` and `dataset_type="spatial_expression"` are gone.
- **Benchmark protocol scorers live with their benchmarks.** MIDOG F1, Monkey FROC and the attention-map rung move to `soma/benchmarks/`; peaks, matching, encoding and point I/O stay core. OCELOT's greedy re-score and the detection ranking driver read the persisted point predictions instead of reloading checkpoints.
- **Point augmentation waits for torchvision 0.23.** Joint augmentation is a `(pixels, target) -> (pixels, target)` callable applied to the live train split (`SegmentationAugment`, an `augmentation: {name, params}` leaf). Point targets are refused until `tv_tensors.KeyPoints` lands (soma#586); that release is the trigger to lift the refusal.

## Consequences

- `SegmentationModel`, `LiveSegmentationModel`, `LiveSegmentationSource`, the segmentation / detection datasets and collates, `bind_segmentation_targets` / `bind_detection_targets`, `_evaluate_grid`, the fold functions for segmentation, detection, pixel classifiers and the probe, `soma/pixel_classifiers/` and `soma/training/probe.py` are deleted, with the unit tests that pinned them.
- Checkpoints name the adaptor `adaptor.*` (was `feature_adaptor.*`); the sliding-window predictor rebuilds `DenseModel`s over one `FrozenEncoder` (`build_dense_models`). Older dense checkpoints with an adaptor do not load without renaming that key prefix.
- Detection binds one level-0 anchor (origin, level-0 pixels per frame pixel) and one spacing per fold; a fold mixing source spacings is refused rather than rescaled per sample.
- The experiment identity moves to v7 (no `pixel_classifier`, `training.method`, `max_train_pixels`; `augmentation` is a leaf), so experiment ids change.
